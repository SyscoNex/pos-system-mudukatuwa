# P1-06 stock operations database review

SysConex approved this package and its operating policies on 29 November 2026. The upgrade from 0009 and the private clean install both reached 0011. Exact package: [0010 stock operations](../database/migrations/0010_stock_operations.sql), [0011 guards](../database/migrations/0011_stock_operation_guards.sql), [runtime grants](../infrastructure/mysql/grant-stock-operations.sh). The clean install used the [private override](../infrastructure/compose.stock-operations-clean.yaml) and published no ports. The existing migration identity, expected database check, checksums and advisory lock apply. The review target retains the Workbench override. SchoolGrid and production are outside scope. [Verification results](27_STOCK_OPERATIONS_IMPLEMENTATION.md)

Seven application tables add transfer headers, reservations, dispatch/receipt/resolution allocations, count roots and count lines. Runtime may read/append allocation facts and read/insert/update the four projection or workflow tables. Guards freeze original request/reservation identities, count snapshots and terminal counts. The existing document, entry and replay immutability and grants survive. Transit requires the canonical TRANSIT location FK and condition. Request lines have no assigned lot; completed ledger entries retain a nonnull lot and the existing exact line/bucket scoped FKs. Scope keys link reservations, request item/lines and stock buckets, and link allocation legs to immutable entries. Exact warehouse, lot, quantity, value, authorization and cumulative constraints across both legs are rechecked transactionally. A paired movement uses two immutable documents in one transaction, so existing document-line warehouse FKs remain intact. Transit legs are internal.

The approved P1-05 costing and expiry policy remains in effect. Source confirmation reserves the full request in FEFO order (dated lots first, then lot and bucket IDs). Source may dispatch in parts. Source or Administrator may cancel the entire undisbursed remainder with a mandatory reason; dispatched quantities remain tracked. Confirm, cancel, dispatch, receive and resolve are actor-scoped durable commands. Receipt value is proportional to the allocation's own residual, with final consumption taking the exact remainder. Returns go into HOLD at the original source. Expired stock may be accepted only into a non-sellable condition. Destination-only access gets the request and shipment manifest without source balance data or historical costs.

A COUNTING row with a generated unique warehouse key is the freeze authority. Counts use versioned actuals and immutable original snapshots. Staff enter counts and Administrator completes or cancels. Completion posts nonzero differences only. Cost is explicitly confirmed for positive variance. Unexpected stock is identified and created within completion so cancellation creates no stock. If a negative variance would breach a reservation, the count remains active and the response identifies the affected request. Cancel it, resolve the reservation, and restart. No automatic release or expiry.

All commands reuse the session/company guard and then read authorized warehouse and freeze state, replay state, workflow head and the affected stock/allocations in stable key order. This serializes P1-05 receipt/opening and organization/catalogue updates too. Independent actual counts do not hold database transactions open. Adjustment and waste are Administrator-only, use explicit reason and immutable documents, and respect reservations and freeze. No condition-only change is introduced.
