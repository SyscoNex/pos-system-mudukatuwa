# P1-07 manufacturing database review

SysConex approved this SQL and policy package on 29 November 2026 for conex360-auth-review and private conex360-p107-clean. The exact package is [0012_production_events.sql](../database/migrations/0012_production_events.sql) and [grant-manufacturing.sh](../infrastructure/mysql/grant-manufacturing.sh). Both installations passed using the existing expected-database check, advisory lock, separate migration identity and migration journal. The review target retained the Workbench override. The [private clean target](../infrastructure/compose.manufacturing-clean.yaml) published no ports. SchoolGrid and production are outside scope. [Verification results](29_MANUFACTURING_IMPLEMENTATION.md)

The only new table is production_events. Its scoped foreign keys bind one PROD document, its warehouse, the OUTPUT line, its item and lot, and the corresponding immutable stock entry. Existing line and stock entry identities continue to enforce company, warehouse, bucket, item and lot relationships. New nullable line roles distinguish INPUT and OUTPUT and an input-group number links FEFO splits to their original entered quantity and unit. Store exact allocations on the input lines. For split rows, entered quantity describes the whole input group and is shown as such. A generated unique slot prevents multiple output lines. Existing records retain NULL roles without a historical backfill. Runtime receives SELECT and INSERT on production_events. Update and delete triggers also protect production facts.

Produced-lot origin is the event's scoped output lot link. The application rejects any existing tracked output lot under the company transaction lock. Existing lots need no inferred provenance or origin flag. Untracked output uses SYSTEM and can have many run links without physical batch lineage. Trace is one hop in each direction. Following the actual intermediate lot connects bulk and packaging runs.

Post completed runs only. The ordinary warehouse must be within the current authorization context and unfrozen. Input FEFO sorts dated lots first, then expiry, lot ID and bucket ID. An explicitly selected eligible bucket is honored before remaining automatic selections. Repeated rows share one provisional balance and carried value per bucket. Input lots must be eligible on both the declared production date and the current company date. Output may be FINISHED or INTERMEDIATE and must be active and manufacture-enabled. Use the production date as the tracked output manufacturing date, with an explicitly entered expiry where required. Expired output is rejected. A tracked production lot code must be new. The output absorbs exactly the sum of rounded input issue values. Six-decimal average cost is derived for display only.

Staff with active outlet access can run ordinary production. Administrator alone can read cost fields and reconcile. Preview and final posting revalidate current company, grant, warehouse version, quantities, costs and expiry. One transaction writes the document, lot and entries, balance updates, event, audit and actor-scoped UUID replay result. Stock history remains immutable. Dependency-aware reversal is future scope.
