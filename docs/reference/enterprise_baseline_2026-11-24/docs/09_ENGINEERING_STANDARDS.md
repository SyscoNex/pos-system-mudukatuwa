# Engineering standards and Git workflow
## Coding
Use meaningful names, small cohesive functions, explicit module boundaries and dependency injection. Avoid magic strings for stable codes; avoid premature abstraction, duplicated business rules and giant services. Nullable reference types and compiler/analyzer checks; deterministic domain logic with injectable clock/ID where useful. Async I/O with cancellation; no blocking .Result; no swallowed exceptions. Dispose connections/transactions and use structured logging. No business mutations in GET requests. DTO validation plus transactional policy validation. Use parameterized SQL and prepared scoped query paths; profile and index actual queries. Use UTC and decimal throughout. Comments explain why and invariants, not syntax.

TypeScript strict, typed API clients from reviewed OpenAPI, lint/format, feature folders, reusable components, no `any` by default, no secrets in client build. Use decimal-safe library for calculations only where needed. Avoid uncontrolled global state and leaking cached tenant data. Keep build lockfile; pin dependencies, review licenses and known vulnerabilities. No scaffolding of unused libraries just to appear enterprise-grade.

## Git proposal
Private organization `SysConex`, repo `conex360` (actual availability not checked). Protected `main`; `develop` optional proposed integration/staging branch (choose at M0); short-lived `feature/INV-02-transfer-dispatch`, `fix/...`, `hotfix/...`. PR required for main, passing checks, reviewer where available, migration and security impact documented; prefer small changes and squash merge if agreed. Tag releases `v0.x.y` initially; changelog and immutable deployment artifacts. Never force-push shared branches or commit secrets. CI should run on PR; production deployment only from approved release/main after protected environment approval. Production credentials isolated from untrusted PRs. No automated deploy of every commit before release gates.

## CI gate proposal
Backend restore/build/test/analyzers; Next.js frontend reproducible locked install/lint/typecheck/test/production build; real MySQL migration clean install and upgrade, guards, integration isolation/posting; secret/dependency scans; package immutable artifacts with version/commit; staging deploy and smoke tests; manual production gate + migration backup checks. Cache dependencies safely. Tests not allowed to point at production. Keep pipeline outputs and sensitive logs scoped; pin external actions to reviewed versions. Document exact runnable commands after scaffold.

## Definition of done
Requirement acceptance criteria implemented with tests, scoped authorization, no direct ledger edits, reviewed schema change, error/retry handling, audit, accessible UX if applicable, docs/decision log updated, reproducible build and test results, operational notes and rollback/compensation plan. No unresolved critical integrity/security defect. For financial feature, accountant-approved mapping and reconciliation; for offline/hardware, device tests. Incomplete modules hidden by server-side flag. Record limitations instead of claiming completion.

## Next.js delivery
At M0 choose and pin compatible Node LTS, Next.js, React and TypeScript versions and one package manager. Commit the lockfile. Run the pinned package-manager clean install, explicit lint (ESLint or approved equivalent), TypeScript typecheck, component tests, Next.js production build and Playwright/equivalent E2E. Do not rely on a framework build alone for linting. Exercise the built Node container in staging; verify route precedence, assets, API calls and tenant-safe caching.
